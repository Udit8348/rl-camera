# CameraLab

CameraLab is a Unity 6 URP MVP for teaching beginner camera fundamentals through an interactive simulation loop:

`SceneState + CameraState -> ShotSimulationService -> SimulationResult -> PostFX + Evaluation + Coaching`

This repo is currently focused on the human-user training simulator. RL integration can be layered on later because the simulation logic is centralized and data-driven.

## What Works

- Sandbox mode
- Guided challenge mode
- Three built-in teaching scenes
- Live preview with exposure, white balance, depth of field, motion blur, shake risk, and noise response
- Capture to PNG with metadata snapshot
- Review screen with transparent scoring and rule-based coaching
- ScriptableObject definitions plus runtime-generated fallback content so the MVP runs in a bare project

## Runtime Architecture

Core runtime flow:

1. [`CameraStateController`](/Users/udit/rl/rl-camera/Assets/CameraLab/Scripts/Core/Controllers/CameraStateController.cs) owns mutable camera settings and clamps them against the active `CameraPreset`.
2. [`SceneStateController`](/Users/udit/rl/rl-camera/Assets/CameraLab/Scripts/Core/Controllers/SceneStateController.cs) loads a `SceneConfig`, builds placeholder content or prefabs, and exposes `SceneState`.
3. [`ShotSimulationService`](/Users/udit/rl/rl-camera/Assets/CameraLab/Scripts/Core/Services/ShotSimulationService.cs) computes the instructionally accurate heuristics.
4. [`SimulationCoordinator`](/Users/udit/rl/rl-camera/Assets/CameraLab/Scripts/Core/Controllers/SimulationCoordinator.cs) recomputes whenever camera or scene state changes.
5. [`PostFXController`](/Users/udit/rl/rl-camera/Assets/CameraLab/Scripts/Rendering/PostFXController.cs) maps the result into URP volume effects and handheld preview jitter.
6. [`ShotEvaluationService`](/Users/udit/rl/rl-camera/Assets/CameraLab/Scripts/Core/Evaluation/ShotEvaluationService.cs) scores the shot.
7. [`CoachingEngine`](/Users/udit/rl/rl-camera/Assets/CameraLab/Scripts/Core/Coaching/CoachingEngine.cs) turns underlying metrics into concise teaching feedback.
8. [`CameraLabUIController`](/Users/udit/rl/rl-camera/Assets/CameraLab/Scripts/UI/CameraLabUIController.cs) presents menus, HUD, and review without owning camera logic or formulas.

## Simulation Model

All major formulas live in [`ShotSimulationService.cs`](/Users/udit/rl/rl-camera/Assets/CameraLab/Scripts/Core/Services/ShotSimulationService.cs).

### Exposure

```text
cameraEV100 = log2((aperture^2) / shutter)
cameraEV    = cameraEV100 - log2(ISO / 100)
exposureOffsetStops = cameraEV - sceneAmbientEV
```

Sign convention used in code:

- Positive `exposureOffsetStops` = underexposed
- Negative `exposureOffsetStops` = overexposed
- Near zero = balanced exposure

This makes the teaching relationships consistent:

- wider aperture lowers EV and brightens the image
- slower shutter lowers EV and brightens the image
- higher ISO lowers EV and brightens the image

### Focus and Depth Of Field

- Subject sharpness comes from `abs(focusDistance - subjectDistance)`.
- Focus tolerance gets more forgiving at narrower apertures and less forgiving at longer focal lengths.
- Background blur potential increases with:
  - wider aperture
  - longer focal length
  - closer subject distance
  - more subject-background separation

### Motion Blur and Shake

- Subject motion blur scales with `shutterSeconds * subjectSpeed`.
- Camera shake risk uses a simplified handheld rule tied to shutter speed, focal length, and scene shake difficulty.
- Tripod nearly removes shake blur.

### Noise

Noise combines:

- ISO-driven noise
- underexposure penalty
- low-light scene pressure

This preserves the beginner intuition that high ISO is noisy, and that rescuing a dark shot makes noise worse.

### White Balance

Presets map to approximate Kelvin targets:

- Auto = scene temperature
- Daylight = `5500K`
- Cloudy = `6500K`
- Shade = `7500K`
- Tungsten = `3200K`
- Fluorescent = `4200K`

Mismatch is the normalized difference between the scene temperature and the selected preset target.

## How To Add A New Scene

1. Create a new `SceneConfig` asset from `Create > CameraLab > Scene Config`, or duplicate one created by `CameraLab/Create Default Content Assets`.
2. Fill in:
   - `ambientEV`
   - `sceneColorTemperatureK`
   - `subjectDistanceMeters`
   - `backgroundDistanceMeters`
   - `subjectSpeedMetersPerSecond`
   - `shakeDifficulty`
   - `defaultCameraSettings`
3. Assign `environmentPrefab` and `subjectPrefab` if you have authored art.
4. If those prefab slots are empty, add a placeholder builder branch in [`PlaceholderSceneFactory.cs`](/Users/udit/rl/rl-camera/Assets/CameraLab/Scripts/Content/PlaceholderSceneFactory.cs).
5. Register the scene in [`BuiltinCameraLabContent.cs`](/Users/udit/rl/rl-camera/Assets/CameraLab/Scripts/Content/BuiltinCameraLabContent.cs) for the runtime fallback path.

No simulation formulas need to change when adding a new scene.

## How To Add A New Challenge

1. Create a `ChallengeConfig` asset from `Create > CameraLab > Challenge Config`.
2. Define:
   - `objectiveText`
   - `targetExposureRange`
   - `targetSharpnessRange`
   - `targetBlurGoal`
   - `targetWhiteBalanceRange`
   - `scoringWeights`
   - `minimumPassScore`
3. Assign the challenge to a `SceneConfig`.
4. If you need new scoring rules, extend [`ShotEvaluationService.cs`](/Users/udit/rl/rl-camera/Assets/CameraLab/Scripts/Core/Evaluation/ShotEvaluationService.cs) instead of adding challenge-specific logic to UI or scene scripts.
